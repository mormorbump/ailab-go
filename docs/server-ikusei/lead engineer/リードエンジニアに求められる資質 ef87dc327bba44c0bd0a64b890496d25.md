# Graffityとして定義すべきこと

### **技術的リーダーシップ**

高い技術力を持ち、チームを技術的にリードする力。

「技術のインプットを楽しみ、惜しみなくアウトプットもする」

「原理原則から推論し、周りに流されず本質を捉えること」 → 仮説検証の話

+プロジェクトの要件から逆算し、正しい技術選定を行う

### **事業理解とプロダクトへの貢献**

事業ドメインへの深い理解を持ち、プロダクトの成長に直接貢献できること。

「ユーザー視点と開発視点のバランスを取る」

「原理原則から推論し、周りに流されず本質を捉える」

「テクノロジーだけでなく、カルチャー理解も大事にする」

### **圧倒的な主体性**

自ら率先して行動し、サービスやプロジェクトの成長を牽引する姿勢。

「積極的な社内知見の発信」

「積極的な外部イベントの参加」

「自分が知らない分野は積極的に専門家を頼る」

### **継続的な成長と変化への適応**

技術変化の激しい環境で、新しい技術を適切に取り入れ、チームに変化をもたらす力。

「過去に執着せず、常に新しい挑戦をする」

「Vision Proや生成AIなどの最新技術を使いこなす」

### **プロジェクト管理とチームの生産性向上**

チームの生産性を最大化し、プロジェクトを成功に導く能力。

「ワークフローの整備、技術・手法の共有を積極的に行い、脱属人化を目指す」

「勉強会を通した継続的なインプット」

「レビュー文化を促進し、スキル成長と品質向上を目指す」

共通言語を確立し、チーム全体で意思決定をサポートする土壌を整える

採用もここに含まれる。プロジェクトのリードがチームに必要な人材の組閣をやれてほしい

この辺りの抽象化したものをどういうふうに思考して、使っていくのか、みたいなのが教育ポイント

→ ハードスキルとソフトスキルの間のOSみたいな感じ

# CTOの仕事

シニアと比べて「採用・営業・技術営業」の要素が強まると考えている

マッツ・コバ・テラは部分的にやっている状況だが、他PJのリードエンジニアもこれを求めるのか

例 : Bulkanの濱田さんにここを求めるのか

## 採用

- 技術スタック
- 人数
- どんな人？

## 教育

- 研修内容
- 継続的な研修、メンター制度
- 社内勉強会

## 技術営業

- 営業の人が困っているときに、ビジネス、お金、技術提案ができると強い

## 技術コンサル

- 営業的なファーストタッチ部分だけでなく、継続的にお客さんの課題を解決する動き
- エンジニアとコンサル両方

## プロジェクトマネジメント

- 重要PJ/新規事業のPM

## 火消し

- マジで問題が起きた時の最終ライン
- ただ、なるべくコードを書くのは現場のメンバーにして、それ以外の責任を持って効率を上げる

## ビジョン

- エンジニアの目線から描く
- これがないと、営業体質の体育会系な会社になってしまう
- エンジニアの視点を持って意見が言える必要がある
- 技術・カルチャー的にいけてて優秀なエンジニアが集まるための土壌

⇒  エンジニアかつコンサルなど、外部に向けた動きができるとかなり強い

```jsx
テックリード

また、チームに変化を生み出すスキルがテックリードには重要です。それが「サービスの継続的進化を担う」という部分に期待されています。
```

```jsx
サービスリード

顧客に支持され続けるサービスの継続的発展に寄与し、サービスづくりの模範となる役割。

ついつい受託出身だと（僕自身がそうなのですが）、ビジネス要件は実現すべき前提条件として盲目的に受け入れてしまいがちですが、そのまま無理やり実装したところで戦闘力のある良いサービスが提供できないのであれば、すべての話をひっくり返さなくてはいけないかもしれません。
そこへのサービス思考力が「高い顧客体験」の実現には不可欠です。その視座を元に高いプロダクトクオリティを実現することがサービスの継続的発展に繋がります。
```
